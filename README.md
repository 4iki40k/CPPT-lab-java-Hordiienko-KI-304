## Поточний стан

Виконано навчальну перевірку JDK та налаштовано компіляцію через Maven Wrapper
(Maven 3.9.11). Додано початковий GitHub Actions для компіляції на Ubuntu,
Windows і macOS. Тести ще не налаштовано.
Предметну програму ще не реалізовано.

## Лабораторна №1 — варіант 9

Заплановано консольну програму для комунальних показників. Вхід — файл UTF-8
без заголовка, один запис на рядок:

```text
meter;date;value;tariff
```

Приклад запису:

```text
Електроенергія;2026-09-01;120.5;4.32
```

Програма має перевіряти записи, повідомляти номер і причину пропуску хибного
рядка та обчислювати кількість коректних записів, сумарне споживання,
загальну вартість і найбільше споживання. Один текст звіту виводитиметься
в консоль і файл. Заплановані параметри: `--help`, `--input`, `--output`, `--version`.

## Поточний навчальний запуск

Потрібен JDK 21. Із кореня репозиторію:

```bash
./mvnw clean compile
java -cp target/classes ua.lpnu.kzp.Hello
```

На Windows замість `./mvnw` використовуйте `.\mvnw.cmd`.
Перевірити версії Maven і Java можна через `./mvnw --version`.
Wrapper завантажує Maven під час першого запуску, але не встановлює JDK.

Якщо у Linux використовується старіша Java, у поточному терміналі оберіть JDK 21
(на цій машині він установлений за наведеним шляхом):

```bash
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk
export PATH="$JAVA_HOME/bin:$PATH"
```

Очікуваний вивід запуску класу:

```text
Привіт, Java!
```

Клас розміщено в `src/main/java/ua/lpnu/kzp/Hello.java`.
Maven записує результати в `target/`, який не входить до репозиторію.
Пакування виконуваного JAR через Maven ще не налаштовано.

## Організація роботи

- `main` — прийняті й перевірені зміни.
- Робота над лабораторними виконується в окремих гілках із Pull Request у `main`.
- Завдання й дефекти фіксуються через GitHub Issues.
- `REPORT.md` містить звіт і облік допомоги ШІ; правила ролей — у `ai/`.

Створено [Issues #1–#7](https://github.com/4iki40k/CPPT-labs-java/issues)
і робочу гілку `lab01`, опубліковану на GitHub. Pull Request ще не відкрито.

## Початковий CI

Workflow `.github/workflows/ci.yml` запускається після push та при відкритті
або оновленні Pull Request. На кожній із трьох ОС він готує JDK 21 Temurin
і виконує `clean compile` через Wrapper. Залежності Maven кешуються.
Цей етап перевіряє лише компіляцію, не тести, запуск програми чи пакування.
Badge вище показує стан робочої гілки `lab01`; після merge його буде оновлено.
