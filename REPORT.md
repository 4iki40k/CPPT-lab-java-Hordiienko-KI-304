# Звіт до лабораторної роботи №1

> Робоча чернетка. Заплановані можливості не є підтвердженими результатами.

## 1. Тема, номер і варіант

- Тема: розгортання Java-проєкту та базова обробка даних.
- Лабораторна робота: №1.
- Варіант: 9 — комунальні показники.
- Операційна система: Linux.
- Репозиторій: https://github.com/4iki40k/CPPT-labs-java

## 2. Мета роботи

Створити консольну програму для обробки комунальних показників та налаштувати
відтворювану збірку, тестування, статичний аналіз і пакування на трьох ОС.
Реалізовано програму варіанта 9 та локально перевірено її розрахунки,
валідацію, CLI, файлові операції, пакування та статичний аналіз.
Локальне технічне рев'ю виконано; статус CI та прийняття змін доступні в PR.
Тег v1.0.0 ще не створено.

## 3. Постановка задачі

Вхід: UTF-8, один запис на рядок, поля `meter;date;value;tariff`.
Обов'язкові текстові поля непорожні; числові поля невід'ємні.
Дата зберігається як текст YYYY-MM-DD, календарний розбір не вимагається.

Показники:

1. Кількість коректних записів.
2. Сумарне споживання: сума `value`.
3. Загальна вартість: сума `value × tariff`.
4. Найбільше споживання: максимум `value`.

Хибні рядки потрібно пропускати з повідомленням номера й причини.
Звіт має виводитися в консоль і файл.

## 4. Структура програми

Пакет — `ua.lpnu.kzp`. Головний клас — `src/main/java/ua/lpnu/kzp/Main.java`.

- `main` викликає `run` та задає код завершення процесу.
- `run` розбирає аргументи, читає UTF-8 CSV, викликає обробку й передає один
  готовий текст у файл і консоль. `--help` та `--version` не читають CSV.
- `validateLine` перевіряє кількість полів, текст, числа та переповнення вартості.
- `buildReport` обходить рядки, накопичує чотири показники та причини пропусків.
- `formatReport` форматує готові показники через Locale.ROOT і `%n`.
- `writeReport` створює каталог за потреби й записує UTF-8 файл.

`data/input.csv` містить три коректні й два хибні записи з українським текстом.
`Hello.java` збережено як навчальний приклад, але він більше не запускається з JAR.
Власні предметні класи поки не вводилися — це основа для лабораторної №2.

## 5. Інфраструктура

Перевірено навчальний запуск через `javac`, `java` та `jar` із JDK 21.
На машині також установлена Java 11, яка була типовою під час початкової
перевірки; для роботи обрано встановлений JDK 21.

Додано базові правила Git, завершень рядків, кодування та відступів.
Налаштовано `pom.xml` із координатами `ua.lpnu.kzp:lab-java:1.0.0`,
цільовою Java 21, UTF-8 і Compiler Plugin 3.13.0.
Глобальний Maven 3.10.0 використано для початкової перевірки та генерації
Wrapper 3.3.4 типу `only-script`; Wrapper запускає Maven 3.9.11.
Додано початковий CI: матриця Ubuntu, Windows і macOS, JDK 21 Temurin,
кеш Maven та `clean compile` через відповідний для ОС скрипт Wrapper.
Workflow запускається на push і pull_request з дозволом `contents: read`.
Підключено JUnit Jupiter 5.12.2 як залежність зі scope `test` та Surefire 3.5.2.
Додано навчальний `HelloTest` для перевірки тестової інфраструктури.
Workflow оновлено з `clean compile` до `clean test` на всіх трьох ОС.
Додано SpotBugs Maven Plugin 4.10.4.1: ціль `check` прив'язано до фази `verify`.
Workflow оновлено до `clean verify`.
Додано Shade Plugin 3.6.2: окремий виконуваний `lab-java-1.0.0-all.jar`,
перший головний клас `ua.lpnu.kzp.Hello`, `Implementation-Version` із версії POM.
Після реалізації програми точку входу змінено на `ua.lpnu.kzp.Main`.
Обидва класи підтримують `--version`; без метаданих JAR показують `development`.
У CI додано звичайний запуск JAR, звіряння версії з POM та публікацію
артефактів із назвами, що містять ОС і номер запуску. Фінальний тег ще не створено.

## 7. Приклади роботи

Студент виконав навчальний цикл:

```bash
javac -encoding UTF-8 Hello.java
java Hello
jar --create --file hello.jar --main-class Hello Hello.class
java -jar hello.jar
```

Повідомлений студентом результат: обидва способи запуску працюють.
Вивід програми: `Привіт, Java!`.
Поточний запуск предметної програми:

```bash
./mvnw clean verify
java -jar target/lab-java-1.0.0-all.jar --input data/input.csv --output out/report.txt
```

Контрольний результат для прикладу даних: 3 коректні записи, споживання 115.00,
вартість 740.00, максимум 100.00, 2 помилки (рядки 4 і 5).
Повний приклад виводу наведено в README. Файл звіту не додається до Git,
оскільки відтворюється запуском програми.

## 8. Тестування

Виконано ручну перевірку навчального класу та JAR.

- `./mvnw --version` — Maven 3.9.11, Java 21.

- `java -cp target/classes ua.lpnu.kzp.Hello` — `Привіт, Java!`.

`-B` вмикає пакетний режим, `-ntp` прибирає індикатори завантажень.

## 9. Документація

Створено й оновлено README і REPORT. Додано javadoc до Main, main та

### Результат технічного рев'ю

Огляд коду й тестів асистентом не виявив блокувальних дефектів.
Повторний локальний `clean verify` успішний: 53 тести, нуль дефектів SpotBugs.
Перевірено валідацію до індексації полів, відсутність часткового оновлення
показників при помилці, порожні дані, UTF-8, незалежність від локалі,
один текст звіту та захист від перезапису вхідного файла.

Неблокувальні обмеження: арифметика double не є банківською; вхідний файл
читається повністю в пам'ять; дата перевіряється лише як непорожній текст.
Це свідомі рішення для лабораторної №1, а не підтвердження придатності
для виробничої системи. Це AI-assisted огляд, не незалежне рев'ю іншого студента.

Формальний пункт для уточнення з викладачем: методичка вимагає номер роботи
та прізвище в назві репозиторію. За рішенням студента використано спільний
репозиторій Java-лабораторних `CPPT-labs-java`; його назву не змінювали.
